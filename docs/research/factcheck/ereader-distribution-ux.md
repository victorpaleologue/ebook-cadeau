# Fact-check report — e-reader distribution and redemption UX

_Fact-check of `docs/research/05-ereader-distribution-ux.md`, 2026-11-12. The corrections below were applied to that document in the same pass (status line: "fact-checked")._

## 0. Method and limits

- **Web search worked.** 12 fresh WebSearch queries, 8 of them in "extended" mode for 2025–2026 changes, written from the claim, not from the document's wording. Vendor pages were not opened; verdicts that rest on the search tool's summary of a page say "per search summary".
- The document itself rests on about 115 primary files read on GitHub (calibre, send2ereader, Kobo specs, Readium, OPDS). Those [V1]/[V2] facts were not re-read here except where a search touched them.
- **Not checked**: PocketBook and Vivlio browser behaviour, `.acsm` handling on devices, tolino cloud, Boox, reMarkable, Bookeen; OPDS and LCP specification details (§4.2–4.3, primary files already read by the researchers); TLS support of e-reader browsers; every [M] menu name.
- Verdicts: CONFIRMED, PARTLY, WRONG, OUTDATED, UNSUPPORTED (no evidence found; not the same as false).

## 2. Omissions and 2025–2026 changes

1. **Kobo OS 6.0 brings LCP** to four current Kobo models outside France first (row 8). When France gets it, Kobo/Fnac becomes a candidate for the LCP lane (R2) on device, not only for account sync.
2. **Kindle DRM-free EPUB/PDF downloads since 20 January 2026** (row 11): an EPUB bought on Amazon can now exist without DRM; the redemption design does not change, the upload gate (doc 09) does.
3. **Send to Kindle verification within 48 hours** and the "harder address" advice (row 4).
4. **Libraries and LCP on Kobo**: loans delivered as `.lcpl` load directly on Kobo OS 6.0 (per search summary) — a sign that a `.lcpl` downloaded by the Kobo browser may open; untested.

## 3. What could not be checked

PocketBook and Vivlio browser download behaviour and user agents; on-device `.acsm` handling; Kobo LCP in France and on older models; the stock Kindle user agent on 5.17/5.18; Google Play Books gifting; Amazon's own Send to Kindle help pages; TLS support of e-reader browsers.

## Code that should change if this correction stands

- `crates/ebc-server/src/device.rs`: no change to the classification rules (they already treat `eReader` as Kobo-or-tolino and a current Kindle as unknown/desktop). If the gift page offers a `.lcpl` (lane R2), the `kobo` class may now get the licence download on Kobo OS 6.0 in the first-round countries; keep it behind a per-country/per-model flag until a device test in France.
- Gift-page copy (`crates/ebc-i18n` strings for the Kindle e-mail route): mention the 48-hour verification e-mail Amazon may send for documents e-mailed to a Kindle address, and keep the app and web routes first.
- `crates/ebc-server` upload gate (doc 09 implication 57): a DRM-free EPUB is no evidence that a file is not a store purchase — unchanged, now confirmed.
- Constants for Send to Kindle (if any): 50 MB e-mail and 200 MB web/app; our 50 MB upload cap stays compatible with the e-mail route.
